# PVE 系統初始化與優化

記錄 PVE 9（Debian 13 Trixie）在台灣環境下的基本優化流程：APT 來源修正、時區校時、移除訂閱提示、必要套件安裝、Datacenter Tag 樣式與 Node Summary 硬體監控。

對應主腳本：[`pve_config_notes.sh`](pve_config_notes.sh)

## 背景

PVE 預設安裝完成後會指向企業付費來源。沒有訂閱金鑰時，`apt update` 會出現 401 Unauthorized；若同時保留傳統 `/etc/apt/sources.list` 與 deb822 `.sources`，也會產生套件來源重複警告。

本腳本會備份既有 APT 設定、移除 PVE／Ceph enterprise source、統一使用 deb822 格式，將 Debian 底層來源改為 TWDS 台灣鏡像 `mirror.twds.com.tw`，並保留 Proxmox 官方 PVE no-subscription source。

## 完成項目

1. **APT 來源**：Debian 使用 TWDS mirror；Debian security 使用 `security.debian.org`；PVE 使用 `pve-no-subscription`。
2. **Enterprise source 清理**：移除 PVE 與 Ceph enterprise source，避免 401 Unauthorized。
3. **時區與時間同步**：設定 `Asia/Taipei`，使用 Chrony 與台灣公開 NTP；可指定內部 NTP。
4. **訂閱提示 Hook**：在 `proxmox-widget-toolkit` 更新後重新套用訂閱提示修補。
5. **監控工具**：安裝 `lm-sensors`、`smartmontools`、`linux-cpupower`、`nvme-cli`、`hdparm`、`jq`。
6. **Datacenter Tag 樣式**：設定完整圓角膠囊與字母排序。
7. **Node Summary**：主腳本會自動下載並執行 `disk_monitor.sh`，套用繁體中文 CPU 與硬碟監控；不需要手動分兩步下載。

## 一鍵安裝

預設安裝不會執行完整 `apt full-upgrade`，避免首次設定立即下載 PVE 核心、韌體與大量套件。

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/pve_config_notes.sh)
```

## 內部 NTP

若機房有內部 NTP 伺服器，可指定它優先校時。IP 僅為範例，請改為實際位址。

```bash
INTERNAL_NTP=192.168.0.100 \
bash <(curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/pve_config_notes.sh)
```

## 完整升級

只有需要同時更新 PVE 核心、韌體與其餘系統套件時，才加上 `--upgrade`。此操作可能下載大量套件，若升級核心，完成後應安排重開機。

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/pve_config_notes.sh) -- --upgrade
```

## Ceph 來源

預設不會加入 Ceph source。只有這台主機確實要安裝或管理 Ceph 時，才加上 `--ceph`；它會建立 Ceph Squid no-subscription source，而不是 enterprise source。

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/pve_config_notes.sh) -- --ceph
```

Ceph 與完整升級一起執行：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/pve_config_notes.sh) -- --ceph --upgrade
```

## 驗證方式

執行完成後，重新登入 PVE Web UI，於節點摘要頁面按 `Ctrl + F5` 強制重新載入。接著可在 shell 檢查：

```bash
sensors
smartctl --scan-open
nvme list
systemctl status chrony --no-pager
```

## 重新套用與還原

PVE 套件更新後若 Node Summary 的客製化顯示消失，可強制重新套用；如需還原官方原始介面，執行還原指令。

```bash
# 強制重新套用硬體監控介面
bash <(curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/pve_config_notes.sh) -- remod

# 還原硬體監控介面
bash <(curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/pve_config_notes.sh) -- restore
```

## 注意事項

- 腳本會將執行前的 APT 設定備份到 `/root/apt-sources-backup-日期時間/`。
- PVE／PBS 版本迭代後，`Nodes.pm`／`pvemanagerlib.js` 的插入點可能改變；請先在測試節點驗證。
- `PkgWatt` 是 CPU 封裝功耗參考值，非整機功耗；整機用電請以 iDRAC、iLO 或 Redfish 等 BMC 介面為準。
- 若主機已有 Ceph、LVM 或重要資料，執行前請先確認現有磁碟與叢集設定，避免將測試流程套用到不適合的生產環境。
