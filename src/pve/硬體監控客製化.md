# PVE 硬體監控客製化

> **正式版：disk_monitor.sh v1.0.52**  
> 更新日期：2026-09-01  
> 實機驗證：已完成

本專案是在 Proxmox VE Node Summary 上加入自訂硬體監控資訊，將 CPU、CPU 溫度、網卡溫度、NVMe、SATA/SAS、MegaRAID Physical Disk 等資料整合到同一個節點摘要畫面。

本文件不只記錄程式功能，也保留實際部署前後的畫面與驗證結果，方便日後重新部署、PVE 升級後重新套用，以及追查 UI 客製化問題。

---

## 1. 專案目的

PVE 原生 Node Summary 已提供基本的 CPU、記憶體、網路與儲存資訊，但實際管理實體伺服器時，仍需要更完整的硬體狀態，例如：

- CPU 即時頻率與 governor
- CPU package 功耗 `PkgWatt`
- 多 CPU / 多插槽溫度
- 網卡感測器溫度
- NVMe SMART 與健康資訊
- SATA / SAS SSD、HDD 分類
- MegaRAID Physical Disk 狀態
- SMART 正常／FAIL／未判定狀態
- 大量硬碟時 Node Summary 自動延伸高度

因此以 `disk_monitor.sh` 建立背景採集機制，再由 PVE UI 顯示已整理好的資料。

核心原則是：**硬體採集在背景執行，PVE API request 不直接執行 smartctl、sensors、turbostat。**

## 3. v1.0.52 更新內容

v1.0.52 的重點不是單純增加幾個文字欄位，而是把資料採集、PVE API、前端 UI Hook 與大量磁碟顯示整合成一套完整流程。

### 3.1 CPU / 溫度

- CPU 即時 MHz
- 平均／最低／最高頻率
- CPU scaling governor
- CPU package `PkgWatt`
- `sensors` CPU 溫度
- 多 CPU / 多插槽分行顯示

CPU 與雙插槽溫度使用精準 Hook，注入在 `render_cpu_model` 後方。

### 3.2 網卡溫度

從 `sensors` 輸出辨識網卡感測器，整理為：

```text
網卡1
網卡2
...
```

避免網卡溫度與 CPU 溫度混在同一段資訊中。

### 3.3 NVMe

顯示：

- 型號
- 溫度
- 健康度
- 通電時數
- 開關機次數
- 讀取 TB / 寫入 TB
- SMART 狀態

### 3.4 SATA / SAS

依 `TRAN` 與 `ROTA` 自動分類：

| 條件 | 類型 |
|---|---|
| `TRAN=sata` + `ROTA=0` | SATA 固態硬碟 |
| `TRAN=sata` + `ROTA=1` | SATA 傳統硬碟 |
| `TRAN=sas` + `ROTA=0` | SAS 固態硬碟 |
| `TRAN=sas` + `ROTA=1` | SAS 傳統硬碟 |

### 3.5 MegaRAID

使用：

```bash
smartctl -d megaraid,N /dev/bus/0
```

掃描 RAID Physical Disk，並透過 Serial / WWN 建立 `/dev/sdX` 與 RAID Physical Disk 的對應，避免 RAID 磁碟被誤列為一般 SATA/SAS 磁碟。

### 3.6 Node Summary Auto-Height

Node Summary 不再依固定高度限制硬碟資訊，使用：

```text
height: "auto", minHeight: 300
```

硬碟數量增加時，容器會跟著內容延伸，避免大量磁碟時資訊被遮住。

## 4. 安裝與套用方式

### 4.1 從 GitHub 取得正式版

```bash
curl -fsSL https://raw.githubusercontent.com/sungshu/pve_config_notes/main/src/pve/disk_monitor.sh -o /root/disk_monitor.sh
chmod +x /root/disk_monitor.sh
```

### 4.2 執行 All-in-One 安裝

```bash
/root/disk_monitor.sh
```

正式版會依目前 PVE 環境處理必要的資料採集、官方檔案備份、Hook 套用與 cron 建立。

### 4.3 背景採集

```bash
/root/disk_monitor.sh collect
```

正式部署後建立：

```text
/etc/cron.d/disk_monitor
```

由 cron 每分鐘執行一次 `collect`，更新 runtime 資料。

### 4.4 重新套用 UI

```bash
/root/disk_monitor.sh remod
```

### 4.5 還原官方 PVE UI

```bash
/root/disk_monitor.sh restore
```

## 7. 更新前／更新後比較

| 項目 | PVE 原生狀態 | v1.0.52 客製化 |
|---|---|---|
| CPU 頻率 | PVE 原生資訊 | 即時 MHz、平均／最低／最高頻率 |
| CPU governor | 未整合於自訂監控區 | 顯示 scaling governor |
| CPU 溫度 | PVE 原生資訊 | 多 CPU / 多插槽分行 |
| 網卡溫度 | 感測器資訊不集中 | 自動整理為網卡1、網卡2… |
| NVMe | 基本儲存資訊 | SMART、溫度、健康度、通電、讀寫 TB |
| SATA / SAS | 儲存裝置資訊 | SSD / HDD 與 SATA / SAS 分類 |
| MegaRAID | 不直接整合 Physical Disk 詳細資訊 | RAID Physical Disk 掃描與對應 |
| SMART | 依硬體環境而定 | 統一整理正常／FAIL／未判定 |
| 大量磁碟 | Node Summary 空間有限 | `height: auto` 自適應 |
| 硬體採集 | PVE 原生機制 | 背景 runtime + cron |
| API request | PVE 原生 API | `Nodes.pm` 只讀取整理後 JSON |

> 這裡的「原生狀態」是本次更新前實機畫面作為基準；表格描述的是本客製化增加的整合能力，不代表 PVE 原生完全沒有任何相關底層資訊。

## 8. 背景資料採集架構

### Runtime

```text
/run/disk_monitor_runtime/
/run/disk_monitor.json
```

### Cron

```text
/etc/cron.d/disk_monitor
```

每分鐘執行 `collect`，由背景流程取得：

- `smartctl`
- `sensors`
- `turbostat`
- `lsblk`
- RAID / Physical Disk 資訊

再整理成 JSON，供 PVE API 與前端 UI 使用。

### API 設計

`Nodes.pm` 不在 API request 期間執行硬體掃描，而是讀取背景採集結果。

因此 UI 開啟 Node Summary 時，不需要每次重新執行完整 SMART / sensors / turbostat 掃描。

---

## 9. 精準 Hook 設計

### CPU Hook

注入點位於 `render_cpu_model` 結尾之後。

```text
CPU Model
  ↓
CPU 運作狀態
CPU 溫度
網卡溫度
```

### 磁碟 / RAID Hook

注入點位於 `pveversion` 區塊結尾之後，將磁碟資訊以全寬區塊向下展開。

### Hook 分離的原因

CPU 與磁碟資訊使用不同 UI 錨點，避免所有資訊集中在同一個前端區塊造成版面錯位，也降低 PVE 前端程式結構變更時的影響範圍。

## 10. 官方檔案備份與還原

正式套用前會依 PVE 版本保存官方檔案：

```text
/var/lib/disk_monitor/<PVE版本>/
```

目的：

1. 保留 PVE 官方原始檔案
2. 方便 `restore`
3. PVE 升級後可以重新建立對應版本的備份
4. 避免舊的注入檔被誤當成新的官方基準

還原：

```bash
/root/disk_monitor.sh restore
```

重新套用：

```bash
/root/disk_monitor.sh remod
```

## 11. 驗證方式

### JSON 格式

```bash
jq empty /run/disk_monitor.json
```

### PVE API

```bash
pvesh get /nodes/localhost/status --output-format json | jq '.cpuFreq,.thermalstate'
```

### 確認 cron

```bash
cat /etc/cron.d/disk_monitor
```

### 確認 runtime

```bash
ls -lah /run/disk_monitor_runtime/
ls -lah /run/disk_monitor.json
```

套用或還原後，瀏覽器執行：

**Ctrl + F5**

避免瀏覽器仍使用舊版 `pvemanagerlib.js` / UI 快取。

## 12. PVE 更新後處理

PVE 更新可能改變：

- `/usr/share/perl5/PVE/API2/Nodes.pm`
- `/usr/share/pve-manager/js/pvemanagerlib.js`
- `/usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js`

因此 PVE 更新後，不應直接假設舊版 Hook 仍適用。

建議流程：

```text
PVE 更新
  ↓
確認 PVE 版本
  ↓
執行 disk_monitor.sh remod
  ↓
確認 API / JSON
  ↓
Ctrl + F5
  ↓
檢查 Node Summary
```

如果需要回到官方 UI：

```bash
/root/disk_monitor.sh restore
```

## 13. v1.0.52 穩定機制

1. **CPU / 雙插槽溫度精準 Hook**：位於 `render_cpu_model` 後方。
2. **磁碟 / RAID 精準 Hook**：位於 `pveversion` 後方。
3. **直通與 RAID 分流**：使用 `raid_idx` / `idx` 判斷，避免 RAID 磁碟被誤列為一般磁碟。
4. **Auto-Height**：支援大量硬碟，不遮擋右側圖表。
5. **All-in-One**：安裝、collect、restore、remod 統一由 `disk_monitor.sh` 管理。
6. **API 非同步採集**：硬體 command 在背景執行，API 只讀取 runtime。
7. **官方檔案備份保護**：依 PVE 版本保存基準檔案。
