# PVE 硬體監控客製化

> **正式版：disk_monitor.sh v1.0.52**  
> 更新日期：2026-09-01  
> 實機驗證：已完成

本專案在 Proxmox VE Node Summary 整合 CPU、CPU 溫度、網卡溫度、NVMe、SATA/SAS、MegaRAID Physical Disk 與 SMART 等硬體資訊。

核心設計是：**硬體資料由背景 `collect` 採集並寫入 runtime，PVE API request 只讀取整理後的 JSON，不在 Web request 期間直接執行 `smartctl`、`sensors`、`turbostat`。**

## 2. disk_monitor.sh v1.0.52

目前正式版本：

```bash
VERSION="1.0.52"
UPDATED="2026-09-01"
```

主要工作分成三層：

```text
┌─────────────────────────────┐
│ disk_monitor.sh             │
├─────────────────────────────┤
│ ① 硬體資料採集              │
│   smartctl / sensors /      │
│   lsblk / turbostat / pvesh │
├─────────────────────────────┤
│ ② Runtime JSON              │
│   /run/disk_monitor_runtime │
│   /run/disk_monitor.json    │
├─────────────────────────────┤
│ ③ PVE UI / API Hook         │
│   Nodes.pm                  │
│   pvemanagerlib.js          │
│   proxmoxlib.js             │
└─────────────────────────────┘
```

### 2.1 CPU

採集：

- CPU scaling governor
- CPU minimum / maximum frequency
- CPU 即時 MHz
- CPU package `PkgWatt`
- CPU / 多插槽溫度
- 網卡感測器溫度

CPU 與多 CPU / 網卡溫度會整理成乾淨的分行資料，避免所有感測器內容直接塞在同一欄。

### 2.2 NVMe

整合 NVMe SMART 與健康資訊，包括：

- 型號
- 溫度
- 健康度
- Power On Hours
- Power Cycle
- Read / Write TB
- SMART 狀態

### 2.3 SATA / SAS

透過 `lsblk` 的 `TRAN` 與 `ROTA` 判斷裝置類型：

| 條件 | 顯示 |
|---|---|
| SATA + SSD | SATA 固態硬碟 |
| SATA + HDD | SATA 傳統硬碟 |
| SAS + SSD | SAS 固態硬碟 |
| SAS + HDD | SAS 傳統硬碟 |

### 2.4 MegaRAID Physical Disk

MegaRAID 使用：

```bash
smartctl -a -j -d megaraid,N /dev/bus/0
```

逐一掃描 Physical Disk，取得型號、Serial、WWN、溫度與 SMART 狀態。

另外建立 RAID Map，優先使用 Serial，再以 WWN 對應 `/dev/sdX` 與 RAID Physical Disk，避免 RAID 磁碟被重複列入一般 SATA/SAS 清單。

### 2.5 SMART 狀態

程式會依 SMART 回傳結果整理成：

```text
OK
FAIL
UNKNOWN
```

不會把無法判定的資料錯誤標示成正常。

## 3. 背景採集架構

Runtime：

```text
/run/disk_monitor_runtime/
/run/disk_monitor.json
```

Cron：

```text
/etc/cron.d/disk_monitor
```

正式部署後由 cron 每分鐘執行：

```bash
/root/disk_monitor.sh collect
```

資料採集完成後，PVE UI 直接讀取已整理好的 runtime JSON。

這個架構的重點是：**開啟 Node Summary 時不需要重新掃描全部硬碟 SMART，也不需要在 API request 裡執行 sensors / turbostat。**

---

## 4. PVE 官方檔案與 Hook

程式處理的官方檔案：

```text
/usr/share/perl5/PVE/API2/Nodes.pm
/usr/share/pve-manager/js/pvemanagerlib.js
/usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js
```

### CPU Hook

CPU 資訊使用精準的 `render_cpu_model` 錨點插入。

### 磁碟 Hook

磁碟 / RAID 資訊使用另一個精準 UI 錨點插入，與 CPU 區塊分離。

### PVE API

`Nodes.pm` 只讀取背景採集結果，不在 request 期間直接執行硬體掃描。

---

## 5. Node Summary 自適應高度

大量硬碟時，固定高度容易造成內容被截斷，因此 Node Summary 採用：

```text
height: "auto"
minHeight: 300
```

磁碟數量增加時，UI 會跟著內容延伸。

## 8. v1.0.52 這次修正重點

v1.0.52 的重點是讓硬體資訊在不同硬體配置下維持正確對應與乾淨顯示。

### 直通 / RAID 判定

修正直通變數判定，使用 RAID Physical Disk index 與一般磁碟 index 的正確變數，避免 RAID 磁碟被錯誤分類。

### 雙精準 Hook

CPU 與磁碟不再共用同一個模糊插入位置，而是使用兩個精準 Hook 錨點。

### 多 CPU / 網卡溫度

感測器輸出重新整理，讓多 CPU、多插槽與網卡溫度保持清楚分行。

## 11. 驗證方式

確認 JSON：

```bash
jq empty /run/disk_monitor.json
```

確認 PVE API：

```bash
pvesh get /nodes/localhost/status --output-format json | jq '.cpuFreq,.thermalstate'
```

確認 cron：

```bash
cat /etc/cron.d/disk_monitor
```

確認 runtime：

```bash
ls -lah /run/disk_monitor_runtime/
ls -lah /run/disk_monitor.json
```

更新 UI 後建議執行瀏覽器：

```text
Ctrl + F5
```

避免瀏覽器仍使用舊版 JavaScript 快取。

## 12. PVE 升級後處理

PVE 更新可能覆蓋官方檔案，因此升級後應重新確認：

```text
Nodes.pm
pvemanagerlib.js
proxmoxlib.js
```

建議流程：

```text
PVE 升級
  ↓
確認官方檔案版本
  ↓
確認 disk_monitor backup
  ↓
重新執行 disk_monitor.sh
  ↓
collect
  ↓
確認 API JSON
  ↓
Ctrl + F5
  ↓
確認 Node Summary
```

不要直接把舊版修改後的 PVE 官方檔案覆蓋到新版 PVE 上。

## 13. 結尾

`disk_monitor.sh v1.0.52` 的目的不是單純把幾個 SMART 數值塞進 PVE Web UI，而是把**硬體資料採集、背景快取、RAID 對應、PVE API、前端 Hook、官方檔案備份與還原**整合成一套可以持續維護的監控方案。

這一版完成後，PVE Node Summary 可以直接看到平常管理實體伺服器真正需要的硬體資訊，同時避免每次開啟 Web UI 都重新執行完整硬體掃描。

實際部署、重新安裝與 Node1 / Node5 前後畫面均已完成驗證；後續如果 PVE 版本升級，只需要重新確認官方檔案與 Hook 錨點，再依本文件流程重新套用即可。

> **這份文件留下的不只是「怎麼安裝」，而是這套 PVE 硬體監控從採集、整合、部署到驗證的完整實戰紀錄。**
